# Scope and memory

Whenever you declare a variable, memory is set aside for it. That memory can be reused once the variable goes out of scope, which happens at the closing brace of the block it was declared in.

```
int main() {
    if (1) {
        int x = 5;
    }
    // x is out of scope: its memory can be reused
}
```

When a variable goes out of scope, its memory is no longer guaranteed to hold the variable's value. A pointer that still holds that address is called a dangling pointer: it points to memory whose contents are undefined.

```
#include <stdio.h>

int main() {
    int *p;
    if (1) {
        int x = 5;
        p = &x;
    }
    printf("%d\n", *p);  // undefined behaviour: x is gone
    return 0;
}
```

gcc even warns about this one: "using dangling pointer 'p' to 'x'". Not every compiler catches it, and the program may still appear to print 5, which is what makes this bug so dangerous.

# A problematic task

Write a function that returns a pointer to some memory containing the integer 5. This version looks reasonable but is wrong:

```
int *getPtrToFive() {
    int x = 5;
    return &x;  // x goes out of scope as the function returns
}
```

x lives in the function's scope. As getPtrToFive returns, x goes out of scope, so the caller receives a dangling pointer. Most compilers warn about this. The fix is to allocate memory that outlives the function:

```
#include <stdio.h>
#include <stdlib.h>

int *getPtrToFive() {
    int *x = (int*)malloc(sizeof(int));
    *x = 5;
    return x;  // heap memory stays until freed
}

int main() {
    int *p = getPtrToFive();
    printf("%d\n", *p);
    free(p);  // the caller is now responsible for freeing it
    return 0;
}
```

Output:

```
5
```

# Global variables

A variable declared outside every function is a global variable. It exists for the whole program and is accessible everywhere.

```
#include <stdio.h>

int glVar = 10;  // global

void setLocal() {
    int glVar;   // a NEW local variable with the same name
    glVar = 20;  // changes the local one only
}

void setGlobal() {
    glVar = 33;  // changes the global
}

int main() {
    setLocal();
    printf("after setLocal: %d\n", glVar);
    setGlobal();
    printf("after setGlobal: %d\n", glVar);
    return 0;
}
```

Output:

```
after setLocal: 10
after setGlobal: 33
```

Declaring int glVar; inside setLocal creates a new local variable that hides the global one. The compiler only changes that local copy, so the global glVar is unchanged.

> Globals are convenient but make programs harder to reason about, because any function can change them. Prefer passing values as parameters.

# Function pointers

You can take the address of a function, store it in a function pointer, and call the function indirectly through that pointer. The only things you can do with a function pointer are assign it and call through it; you cannot do arithmetic on it.

```
#include <stdio.h>

int Add(int num1, int num2) {
    return num1 + num2;
}

int Subtract(int num1, int num2) {
    return num1 - num2;
}

int main() {
    // same return type and parameter types as the function
    int (*functionPtr)(int, int);

    functionPtr = Add;
    printf("%d\n", functionPtr(20, 10));

    functionPtr = Subtract;
    printf("%d\n", functionPtr(20, 10));
    return 0;
}
```

Output:

```
30
10
```

> The brackets in int (*functionPtr)(int, int) matter. Without them, int *functionPtr(int, int) declares a function that returns an int pointer.

@quiz
? When does a local variable go out of scope?
- When the program ends
* At the closing brace of the block it was declared in
- When it is assigned a new value
- Never
! A variable only exists inside the block where it is declared.

? What is a dangling pointer?
- A pointer set to NULL
* A pointer to memory whose contents are no longer valid
- A pointer to a pointer
- A pointer that has not been declared
! Using it is undefined behaviour: the memory may now hold anything.

? Why is returning &x from a function wrong when x is a local variable?
- & cannot be used in a return statement
* x goes out of scope when the function returns, so the pointer dangles
- It returns the value instead of the address
- It is fine as long as x is an int
! The local x is gone once the function returns.

? What does this print?
```
int g = 1;
void f() {
    int g = 2;
    g = 3;
}
int main() {
    f();
    printf("%d", g);
}
```
* 1
- 2
- 3
- 0
! f declares its own local g, which hides the global. The global g stays 1.

? Which declares p as a pointer to a function taking two ints and returning an int?
- int *p(int, int);
* int (*p)(int, int);
- int p*(int, int);
- (int *)p(int, int);
! The brackets around *p make p a pointer rather than a function returning int *.

? What can you NOT do with a function pointer?
- Assign a function to it
- Call the function through it
* Add 1 to it to reach the next function
- Store it in a variable
! Arithmetic on function pointers is not allowed.

? What does this print?
```
int g = 1;
void setGlobal() { g = 5; }
int main() {
    setGlobal();
    printf("%d\n", g);
}
```
- 1
* 5
- 6
! There's only one g, the global one, and setGlobal changes it.

? What does this print?
```
int g = 1;
void setLocal() { int g = 5; g++; }
int main() {
    setLocal();
    printf("%d\n", g);
}
```
* 1
- 5
- 6
! setLocal declares its own g, which hides the global one and disappears when the function ends.

? What does this print?
```
int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }
int main() {
    int (*op)(int, int) = mul;
    printf("%d\n", op(3, 4));
}
```
- 7
* 12
- 34
! op points at mul, so op(3, 4) calls mul.

? Where does a variable declared inside a block { } exist?
* From its declaration to the end of that block
- Everywhere in the file
- Until the program ends
- Only in the function that called the block
! That's its scope. Outside the block the name means nothing (or a different variable).

? Why are global variables often avoided?
- They are slower than local variables
* Any function can change them, which makes bugs hard to trace
- They can only hold ints
- They are deleted after each function call
! When many functions can change a value, finding which one changed it wrongly is hard.

@solution
```
#include <stdio.h>

int Add(int num1, int num2) {
    return num1 + num2;
}

int Subtract(int num1, int num2) {
    return num1 - num2;
}

int main() {
    int (*op)(int, int) = Add;
    printf("10 + 4 = %d\n", op(10, 4));
    op = Subtract;
    printf("10 - 4 = %d\n", op(10, 4));
    return 0;
}
```
! A function pointer is a variable like any other: assigning it a different function changes what op(10, 4) calls, without changing the call itself.
