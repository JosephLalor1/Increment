@title Reading Input with scanf

printf writes to the screen. Its partner scanf reads from the keyboard. You give scanf a format string, just like printf, and the address of each variable to fill.

```
#include <stdio.h>

int main() {
    int age;
    float salary;
    char initial;
    // stdin: 25 1500.50 J

    printf("Enter your age: ");
    scanf("%d", &age);      // & means "address of"

    printf("Enter your salary: ");
    scanf("%f", &salary);

    printf("Enter your initial: ");
    scanf(" %c", &initial); // space before %c skips whitespace

    printf("\nYou entered:\n");
    printf("Age: %d\n", age);
    printf("Salary: %.2f\n", salary);
    printf("Initial: %c\n", initial);
    return 0;
}
```

Output:

```
Enter your age: Enter your salary: Enter your initial:
You entered:
Age: 25
Salary: 1500.50
Initial: J
```

# Why the & ?

scanf has to store the value into your variable, so it needs to know where that variable lives in memory. &age means "the address of age". Forgetting the & is a very common bug: scanf then writes to a random place in memory. You will see much more of & in the pointers lessons.

# Why the space in " %c" ?

When you press Enter after typing a number, the newline character is left waiting in the input. %d and %f skip leading whitespace automatically, but %c does not: it would read that leftover newline as the character. The space in " %c" tells scanf to skip any whitespace first.

# Prompts that appear late

On some online compilers, such as cpp.sh, the "Enter your..." prompts are not shown until the program ends, because output is held back until a newline is printed. The fix is to end each prompt with \n:

```
printf("Enter your age: \n");
```

# scanf in Visual Studio

Visual Studio treats scanf as unsafe and refuses to compile it by default (error C4996). It suggests scanf_s instead. scanf returns the number of values it successfully read, so you can also check that the input was valid:

```
if (scanf_s("%d", &age) != 1) {
    printf("Invalid input for age.\n");
    return 1;
}
```

> With scanf_s, %c and %s need an extra argument giving the buffer size: scanf_s(" %c", &initial, 1). Alternatively, put #define _CRT_SECURE_NO_WARNINGS on the very first line of the file and keep using scanf.

@solution
```
#include <stdio.h>

int main() {
    int a, b;
    printf("Enter two numbers: ");
    scanf("%d %d", &a, &b);
    printf("%d + %d = %d\n", a, b, a + b);
    return 0;
}
```
! scanf stores what it reads at an address, so every variable needs its &. Without it, scanf takes b's garbage value as an address and writes somewhere it shouldn't. (The numbers typed in don't appear in the output, because they're input, not something the program prints.)
