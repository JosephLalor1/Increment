@title Dynamic Memory: malloc and free

Ordinary variables live on the stack and disappear when they go out of scope. Sometimes you need memory that lasts longer, or whose size you only know while the program runs. C gives you that memory from the heap with malloc, and you hand it back with free. Both are declared in <stdlib.h>.

# Allocating a single value

malloc takes a number of bytes and returns a pointer to that much new memory. Use sizeof to get the right number of bytes for a type.

```
#include <stdio.h>
#include <stdlib.h>

int main() {
    // Allocate memory for a single integer
    int *ptr = (int*)malloc(sizeof(int));

    if (ptr == NULL) {
        printf("Memory allocation failed!\n");
        return 1;
    }

    *ptr = 42;  // use the allocated memory
    printf("Value: %d\n", *ptr);

    free(ptr);  // free the memory when done
    return 0;
}
```

Output:

```
Value: 42
```

# Allocating an array

Multiply the element size by how many elements you need. The result can be used exactly like an array.

```
#include <stdio.h>
#include <stdlib.h>

int main() {
    int size = 5;
    int *arr = (int*)malloc(size * sizeof(int));

    if (arr == NULL) {
        printf("Memory allocation failed!\n");
        return 1;
    }

    for (int i = 0; i < size; i++) {
        arr[i] = i * 10;
    }

    printf("Array elements: ");
    for (int i = 0; i < size; i++) {
        printf("%d ", arr[i]);
    }
    printf("\n");

    free(arr);
    return 0;
}
```

Output:

```
Array elements: 0 10 20 30 40
```

> size could come from the user at run time. That is the big advantage over int arr[5], whose size is fixed when you write the program.

# Key points to remember

- Always check whether malloc returned NULL: allocation can fail.
- Always call free() for every successful malloc() to avoid memory leaks.
- Use sizeof() to get the correct size of the data type.
- Don't use memory after freeing it: this causes undefined behaviour.
- Set a pointer to NULL after freeing it. It is good practice, because a NULL pointer can be checked, while a freed one looks valid but is not.

```
free(arr);
arr = NULL;   // arr no longer looks like a valid pointer
```

# Memory leaks

A leak happens when you lose the only pointer to some allocated memory before freeing it. The memory stays allocated until the program ends, and nothing can use it.

```
int *p = (int*)malloc(sizeof(int));
p = (int*)malloc(sizeof(int));  // the first block is now lost
free(p);                        // only frees the second block
```

```memory
title How the first block leaks
> int *p = (int*)malloc(sizeof(int));
heap first int ?
var p int* &first
say p points to a new int on the heap.
> p = (int*)malloc(sizeof(int));  // the first block is now lost
heap second int ?
set p &second
say p now points to a second block. Nothing holds the first block's address any more, so it can never be freed. Click the first block to see.
> free(p);                        // only frees the second block
free p
say free(p) frees the block p points to, the second one. The first block stays allocated, unreachable, until the program ends: a memory leak.
```

- free requires it
- It frees the memory a second time

```
#include <stdio.h>
#include <stdlib.h>

int main() {
    int n;
    scanf("%d", &n);
    int *squares = (int*)malloc(n * sizeof(int));
    if (squares == NULL) {
        printf("No memory\n");
        return 1;
    }
    for (int i = 0; i < n; i++) {
        squares[i] = (i + 1) * (i + 1);
    }
    for (int i = 0; i < n; i++) {
        printf("%d ", squares[i]);
    }
    printf("\n");
    free(squares);
    return 0;
}
```
! The size is only known while the program runs, so the array has to come from the heap. malloc(n * sizeof(int)) asks for exactly enough bytes, and free hands them back so they don't leak.
